---
title: 排查基岩版连接与 UDP 端口
description: 按版本、地址、局域网、防火墙和公网入口的顺序定位 BDS 连接失败
---

基岩版玩家连不上 BDS 时，先不要同时修改端口、路由器、客户端和服务器配置。一次只确认一个环节，才能知道问题真正出现在哪里。下面的顺序从最靠近服务端的条件开始，适合“服务器看起来已启动，但玩家无法进入”的情况。

## 1. 先确认客户端与服务端版本

如果客户端提示 **Outdated Client** 或 **Outdated Server**，优先处理版本同步。Microsoft 的 BDS 文档说明，这类提示通常表示客户端与服务端协议版本不匹配；更新过旧的一方后，再重新测试连接。[1]

## 2. 确认玩家填写的是正确地址与端口

局域网玩家应填写运行 BDS 主机的局域网 IP，而不是服务端目录、电脑名称或路由器管理地址。端口应与 `server.properties` 中的 `server-port` 一致。若你修改过端口，玩家输入、BDS 配置和防火墙规则必须同步调整。

| 测试场景 | 推荐填写方式 | 常见误区 |
| --- | --- | --- |
| 同一局域网 | 主机的局域网 IP 与 `server-port` | 把 `127.0.0.1` 填到另一台设备上。 |
| 服务端所在 Windows 主机 | 按官方 loopback 说明或使用另一台局域网设备测试 | 以本机无法连接直接判断服务端损坏。 |
| 外网玩家 | 公网地址或你已验证的域名与映射端口 | 用家庭内网测试代替真正外部网络测试。 |

## 3. 验证主机防火墙允许 UDP

BDS 的 `server-port` 和 `server-portv6` 需要被主机防火墙允许。官方文档以 19132 和 19133 为默认示例，但你应以实际 `server.properties` 为准。[1] 对云主机，还要检查云平台安全组或网络防火墙是否另有一层 UDP 限制。

不要为了“快速测试”把整台主机的防火墙永久关闭。更安全的做法是创建只针对实际 UDP 端口的入站规则，测试结束后保留必要范围、删除临时放开的规则。

## 4. 最后才测试路由器或公网入口

只有局域网连接已经成功，才值得继续检查路由器端口映射、运营商公网地址、CGNAT 或托管主机网络规则。映射时协议应与 BDS 的 UDP 需求一致，外部端口、内部主机地址和内部端口应与你记录的配置相匹配。

使用手机流量或让外部朋友测试，避免家庭路由器的回环行为影响结论。若外部失败而局域网成功，保留以下信息再寻求帮助：BDS 版本、客户端版本、`server-port` 值、是否使用 IPv4/IPv6、主机防火墙规则和外部测试方式。提交截图或日志前先打码公网地址与账号信息。
