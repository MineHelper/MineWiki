这一页以 Minecraft Java 版的 Paper 服务端为例。目标很简单：先让服务端在本机稳定启动，确认世界、日志和关闭流程正常；公网联机留到后面处理。这样出了问题时，范围会小很多。

<Steps>
  <Step number="1" title="下载与游戏版本匹配的服务端">
    从 Paper 官方下载页获取 jar，并放进一个专门的空文件夹。
  </Step>
  <Step number="2" title="写启动脚本">
    脚本中的 jar 名称、Java 版本和内存参数必须与实际环境一致。
  </Step>
  <Step number="3" title="首次启动并确认 EULA">
    第一次运行会生成文件并要求接受 Minecraft EULA；这是正常流程，不是安装失败。
  </Step>
  <Step number="4" title="本机验证与安全关闭">
    控制台完成启动后先连接 `localhost`，再用 `stop` 关闭并确认世界已保存。
  </Step>
</Steps>

## 1. 下载并整理文件

到 [Paper 官方下载页](https://papermc.io/downloads/paper)选择与你的客户端匹配的 Minecraft 版本和构建，下载 jar 文件。不要把服务端直接丢在下载目录或桌面；新建一个独立文件夹，例如 `D:\MinecraftServer\` 或 `~/minecraft-server/`，把 jar 放进去。

Paper 的可用 Minecraft 版本和对应 Java 版本会变化。不要依赖“Paper 只支持某个版本以上”之类的旧说法；以 [Paper 的当前入门文档](https://docs.papermc.io/paper/getting-started/)和下载页为准。

## 2. 创建启动脚本

Windows 下，在与 jar 同一目录创建 `start.bat`。下面示例中的 `paper.jar` 必须改成你的实际文件名：

```bat
@echo off
java -Xms2G -Xmx4G -jar "paper.jar" --nogui
pause
```

Linux 下可以创建 `start.sh`：

```bash
#!/usr/bin/env bash
set -euo pipefail
java -Xms2G -Xmx4G -jar "paper.jar" --nogui
```

然后执行 `chmod +x start.sh`，再用 `./start.sh` 启动。`-Xms` 是初始堆内存，`-Xmx` 是最大堆内存；示例数值只适合小型起步服务器，请按[内存规划](/tools/memory-plan)和实际负载调整。`--nogui` 会关闭原版图形界面，命令行启动时推荐保留它。[Paper 官方示例](https://docs.papermc.io/paper/getting-started/)使用的也是这一写法。

<Callout tone="tip" title="不想手写脚本？">
  可以直接使用[启动脚本生成器](/tools/start-script)。它会按 Windows 或 Linux 输出脚本，但 jar 文件名仍应由你核对。
</Callout>

## 3. 第一次启动与 EULA

运行脚本后，服务端会创建 `eula.txt` 等基础文件，并停止运行，控制台通常会提示：

```text
You need to agree to the EULA in order to run the server.
```

打开 `eula.txt`，将 `eula=false` 改为 `eula=true` 并保存。这样做表示你同意 [Minecraft EULA](https://www.minecraft.net/eula)。随后再次运行脚本。

<Callout tone="warning" title="第一次停止不等于 Java 安装失败">
  如果日志明确提示 EULA，只需先完成 EULA 流程。只有出现 `UnsupportedClassVersionError`、`Unable to access jarfile` 等错误时，才需要回头检查 Java 版本或脚本里的 jar 名称。
</Callout>

## 4. 本机验证

第二次启动后，服务端会生成世界和默认配置。控制台出现 `Done` 之类的“启动完成”信息后，在同一台电脑的客户端中添加服务器地址：

```text
localhost
```

若你改过 `server-port`，则使用 `localhost:端口`。本机能进入，只能证明服务端和本机网络路径正常；它不能证明端口转发或内网穿透已经配置正确。

## 5. 常用控制台命令

| 命令 | 用途 | 使用建议 |
| --- | --- | --- |
| `list` | 查看在线玩家 | 排查连接时确认服务端是否仍有响应。 |
| `op 玩家名` | 授予 OP | 只给可信管理员；长期管理建议使用权限插件。 |
| `save-all` | 请求保存世界 | 可在维护或备份前执行，但不替代完整备份。 |
| `stop` | 保存并正常关闭服务端 | 日常关服应优先使用。 |

## 6. 启动失败时先看哪里

1. 先打开 `logs/latest.log`；它通常比窗口里一闪而过的文字完整。
2. `UnsupportedClassVersionError`：脚本调用的 Java 版本不符合服务端要求。
3. `Unable to access jarfile`：脚本中的文件名或工作目录不对，注意 Windows 可能隐藏扩展名。
4. `Address already in use` 或 `bind failed`：端口已被占用，或 `server-ip` 填错。家用单服的 `server-ip` 通常应留空。[Paper 官方排错指南](https://docs.papermc.io/paper/basic-troubleshooting/)也将这两项列为常见原因。
5. 配置相关错误：先备份，再检查最近改过的文件；不要把删除 `server.properties` 当作第一反应。

## 7. 正确关闭服务端

在控制台输入 `stop`，等待进程自行退出。直接关闭窗口、断电或强制结束进程会增加未写完世界数据的风险。准备更新、装插件或大改配置前，请先按[备份与恢复](/docs/maintenance/backup)创建可还原的备份。
