上一篇讲了开服前要想清楚的事，这篇直接把第一个服务器跑起来。我们以 Java 版、Paper 服务端为例，其他服务端流程大同小异。

<Steps>
  <Step number="1" title="下载服务端">
    从 Paper 官方下载页获取与你的 Minecraft 版本匹配的 jar 文件，并放进一个独立文件夹。
  </Step>
  <Step number="2" title="创建启动脚本">
    Windows 使用 `start.bat`，Linux 使用 `.sh` 脚本；文件名要和实际 jar 文件完全一致。
  </Step>
  <Step number="3" title="首次启动并同意 EULA">
    第一次启动失败是正常现象。编辑 `eula.txt` 后再启动，服务端才会继续生成文件。
  </Step>
  <Step number="4" title="本机验证后再联机">
    看到 `Done` 后先用 `localhost` 测试；本机稳定后，再继续配置端口转发或内网穿透。
  </Step>
</Steps>

## 下载服务端

服务端不是从启动器里下载的。你需要到 [Paper 官方下载页](https://papermc.io/downloads/paper) 下载 Paper 的 jar 文件。

选版本的时候注意：Paper 只支持 1.16.5 及以上的版本，玩老版本（比如 1.8）只能用 Spigot 或者官方原版服务端。不要用别人二次打包、加了所谓"优化"的整合 jar，来源不明的东西你永远不知道里面塞了什么。

下载完得到一个类似 `paper-1.21.1-131.jar` 的文件。给这个 jar 建一个独立的文件夹放好，别和下载目录混在一起——后面会生成一堆文件，全堆在桌面你会崩溃。

## 第一次启动

用一个 `.bat`（Windows）或者 `.sh`（Linux）启动脚本启动服务端。Windows 下新建文本文件，改成 `start.bat`，内容：

```bat
@echo off
java -Xmx4G -jar paper-1.21.1-131.jar nogui
pause
```

几个说明：

- `-Xmx4G` 是最大内存，根据上一篇的规则改。
- `nogui` 表示不启动图形界面，纯命令行跑，省资源。
- 记得把 jar 文件名改成你实际下载的文件名。

双击运行。第一次启动一定会失败，这是正常的，看提示：

```text
You need to agree to the EULA in order to run the server.
```

到服务器文件夹里找到 `eula.txt`，把 `eula=false` 改成 `eula=true`，保存，再启动。这一步没有别的办法绕过，Mojang 和 Paper 都要求你确认同意用户协议。

<Callout tone="warning" title="第一次启动失败是预期行为">
  不要因为第一次启动报错就反复重装 Java 或重新下载 jar。先按提示同意 EULA，再检查脚本里的 jar 文件名是否正确。
</Callout>

## 生成世界并进入

第二次启动会开始生成世界，时间取决于电脑性能，几分钟不等。看到 `Done (12.345s)! For help, type "help"` 就算启动完成。

服务端窗口保持开着，用 Minecraft 客户端连接 `localhost` 就能进去测试。能进本地，接下来才需要考虑让别人能进来。

## 常用的几个服务端命令

在服务端控制台直接输入：

- `list` 查看在线玩家
- `op 玩家名` 给予管理员权限
- `save-all` 手动保存世界
- `stop` 安全关闭服务器（直接关窗口可能会损坏世界）

## 关服的正确姿势

<Callout tone="danger" title="不要直接关闭服务端窗口">
  直接点窗口右上角的叉，或者 `kill` 掉进程，可能让世界文件没有完成写入。正确做法是在控制台输入 `stop`，等它跑完存档流程再关。
</Callout>

## 我该用原版还是 Paper

一句话总结：想要原汁原味就下官方的 `server.jar`，想要更好的性能和插件支持就上 Paper。两者的启动逻辑完全一样，上面这套流程同样适用。

## 遇到问题先自查

启动失败的报错里，绝大多数信息都是有用的，别跳过。常见的几类：

- `UnsupportedClassVersionError`：Java 装错了，回上一篇看版本对应表。
- `Port 25565 already in use`：端口被占用，检查是不是已经开了一个服务端，或者改 `server.properties` 里的端口。
- `Failed to load properties file`：配置被写坏了，删掉 `server.properties` 让它重新生成。

如果报错看不懂，把完整的日志贴给搜索引擎或问人，比只报一句"开服失败"有用得多。日志在 `logs/latest.log`，用记事本打开就能复制。
