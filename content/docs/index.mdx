Minecraft 的 Java 版与基岩版使用不同的服务端软件、客户端生态和扩展方式。第一次开服时，最重要的选择不是先改配置，而是先确定你的玩家主要使用哪一个版本；选错路线后，后续的插件、模组、端口、资源包和管理命令都可能不适用。

<Callout tone="info" title="先按玩家使用的客户端选择">
  想让使用 Minecraft Java Edition 的电脑玩家加入，请进入 Java 版教程。想为 Windows、手机、平板或主机上的 Bedrock Edition 玩家部署独立服务器，请进入基岩版教程。两者不能把同一套服务端文件直接互换使用。[1] [2]
</Callout>

## 两条路线的主要区别

| 关注点 | Java 版 | 基岩版 |
| --- | --- | --- |
| 官方独立服务端 | Java Edition Server；也可按需求选择 Paper、Fabric 或 NeoForge 等生态。 | Bedrock Dedicated Server（BDS），官方提供 Windows 与 Ubuntu 版本。[2] |
| 扩展方式 | 插件与模组是两套不同生态，服务端类型要与扩展格式匹配。 | 以资源包、行为包和 Add-On 为主要扩展形式，不等同于 Java 版插件或模组。 |
| 常见联机端口 | 以服务端的 TCP 配置为准；Java 教程会单独说明网络前提。 | BDS 使用 `server.properties` 中的 UDP 端口；官方资料示例默认使用 19132 与 19133。[3] |
| 版本兼容 | 客户端、服务端、加载器与扩展需按各自生态核对版本。 | 客户端和 BDS 的协议版本不一致时，可能出现 Outdated Client 或 Outdated Server，应先同步版本。[3] |

这里的分类只用于帮助你开始；如果你的目标是让 Java 与基岩版玩家共同游玩，请先完成其中一条主路线，再阅读跨版本联机的专门说明。不要把跨版本桥接当作“同一种服务端”，也不要直接套用另一版本的配置样例。

## 阅读方式

每个版本板块都按相同的任务顺序组织：先了解服务端和环境，再完成首次启动与联机，然后进入配置、日常管理和扩展内容。子目录的页面会在侧栏中展开；如果你只想解决一个明确症状，也可以从常见问题入口开始，但处理涉及世界、权限或网络的操作前仍应先备份并记录原始配置。

<Callout tone="tip" title="不确定该选哪一个？">
  先问准备一起玩的玩家：他们启动游戏时使用的是 Java Edition 还是 Bedrock Edition。以大多数实际玩家的客户端为准，再进入对应的板块；不要只根据设备品牌或“手机版/电脑版”这类说法猜测。
</Callout>
