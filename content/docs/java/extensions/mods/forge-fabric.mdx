title: Forge、NeoForge 还是 Fabric
description: 不从“谁更强”出发，而是用目标整合包和核心模组决定加载器
---

选择加载器最可靠的原则只有一条：**你要运行的整合包或核心模组决定加载器。** Forge、NeoForge 和 Fabric 不是可以随意互换的三个“性能模式”；它们有不同的 API、依赖和发布生态。

## 先看兼容性，再谈偏好

| 你手上的需求 | 合理的选择 |
| --- | --- |
| 整合包页面明确写 Forge、NeoForge 或 Fabric | 完全按整合包要求安装，不要自行换加载器。 |
| 有一个必须使用的核心模组 | 到模组的官方发布页确认它支持的 Minecraft 版本和加载器。 |
| 想自己组包 | 先列出 5–10 个关键模组与依赖，找出共同支持的加载器和版本，再开始安装。 |
| 只是想开一个轻量服务端 | 仍先看实际模组是否存在目标加载器版本；不要只根据“听说更快”选择。 |

Modrinth 和 CurseForge 的项目页通常会标示 Minecraft 版本和加载器。Fabric 官方也明确提醒，模组必须匹配正确的 Minecraft 版本和 Fabric，而不能与其他加载器的构建混用。[Fabric：Installing Mods](https://docs.fabricmc.net/players/installing-mods)

## Forge、NeoForge 与 Fabric 的关系

- **Forge**：长期存在的模组加载器，许多旧整合包和旧模组明确要求它。
- **NeoForge**：独立的现代加载器项目；不少新项目会明确发布 NeoForge 版本。它不是“Forge 改名”，也不能替代一个明确要求 Forge 的旧整合包。
- **Fabric**：另一套独立生态。许多 Fabric 模组还依赖 Fabric API；Fabric jar 不能放到 Forge 或 NeoForge 服务端。

因此，正确问题不是“哪个加载器更好”，而是“我的整合包、核心模组、依赖和服务端是否都明确支持同一套加载器与同一 Minecraft 版本”。

## 常见误区

**同名模组的不同构建可以混用吗？** 不可以。Forge、NeoForge 和 Fabric 版本通常是不同二进制文件，依赖关系也不同。

**新版本一定选 Fabric 吗？** 不一定。加载器与模组的适配速度会随项目、Minecraft 版本和作者计划变化；请看具体发布页，不要用通用印象替代兼容性检查。

**可以把 Paper 插件放进模组服吗？** 常规 Forge、NeoForge 或 Fabric 服务端不加载 Bukkit/Paper 插件。若某个混合服务端声称兼容两种生态，应先阅读它的官方兼容性与风险说明，并在测试副本上验证。

## 实用检查清单

1. 记录 Minecraft 完整版本号，例如 `1.21.1`，不要只写 `1.21`。
2. 记录加载器及其版本。
3. 记录每个核心模组、前置库和配置文件的版本。
4. 首次成功启动后，将这份清单与整服备份一起保存。

继续阅读[安装模组服](/docs/java/extensions/mods/install)，了解服务端包、启动脚本和客户端同步的实际步骤。
