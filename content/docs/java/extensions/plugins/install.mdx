## 插件安装与配置

## 安装步骤

插件安装非常简单，就三步：

1. 把下载的插件 `.jar` 直接放进服务端根目录下的 `plugins/` 文件夹；不要放在它的子目录里。
2. 正常重启服务端（控制台输入 `stop`，等待退出后再启动）。
3. 启动时检查 `logs/latest.log`，再用 `plugins` 控制台命令或 `/plugins` 确认插件是否已启用。

第一次加载完看一眼日志，确认没有报错。插件自己的报错会打印在日志里，别忽略。

## 配置在哪里

很多插件会在 `plugins/<插件名>/` 下生成配置目录，常见主文件名是 `config.yml`，但具体结构由插件作者决定。除非插件官方文档明确说明某项可以热重载，否则改完配置后应正常重启服务端。

不要把服务端的 `reload` 当作日常操作。它可能让插件状态、任务或依赖关系处于不一致状态；需要重新加载时，优先使用插件作者明确提供且说明安全的命令，或直接重启。

## 依赖插件

有些插件需要先装另一个插件才能工作（依赖项），比如：

- 需要 `Vault` 才能用的经济/领地类插件。
- 需要某个前置库（如 `PlaceholderAPI`）的扩展插件。

装插件时留意下载页写的依赖要求。缺少前置时，`logs/latest.log` 往往会指出缺失的插件或库；安装前仍要确认该依赖与服务端和目标插件版本兼容。

## 装完必做的三件事

1. **看启动日志**：确认插件加载成功、没有红色报错。
2. **进服测试核心功能**：别在服里敲个命令没反应就完事，把 `config.yml` 里的核心功能都过一遍。
3. **别一口气装几十个插件**：装一个测一个，出问题好定位。全装上再慢慢排查，你根本不知道是谁在打架。

## 常见问题

**Q：装了插件没生效？**
先重启服务端；再看日志有没有报错；再确认是不是漏了依赖；最后检查插件和服务端版本是否匹配。旧版插件强行用在新服务端上，经常静默失效。

**Q：插件起冲突怎么办？**
两个插件干同一个活（比如两个领地插件）最容易冲突。要么只留一个，要么看两者文档确认兼容设置。日志里的报错会提到具体类名或插件名，贴到搜索引擎搜一下。

**Q：插件在哪都能下吗？**
参考《插件入门》里的渠道选择，来源不明的 jar 别装。插件 jar 是会在服务端进程内运行的代码，因此来源、版本和依赖都应可追溯。
