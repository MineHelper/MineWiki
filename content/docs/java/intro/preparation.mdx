第一次开服不需要把配置一次配到位。更可靠的做法是：先明确要开什么服，在本机跑通最小方案，再按玩家数量和实际性能逐步增加功能。

## 先确定服务器类型

| 目标 | 常见选择 | 需要优先考虑的事 |
| --- | --- | --- |
| 原版体验 | 官方 `server.jar` | 版本、备份和基本联机。 |
| 原版玩法加管理功能 | Paper | 插件版本、权限和性能定位。 |
| 现成整合包 | Forge、NeoForge 或 Fabric 的服务端包 | 客户端与服务端的加载器、Minecraft 版本和模组列表。 |
| 多玩法或多服网络 | 多个后端服务端加代理 | 网络隔离、权限、监控和回滚；不适合作为第一次练手项目。 |

如果你还没有明确目标，建议从一台 Paper 生存服开始。它能让你完整走一遍 Java、服务端、日志、备份和插件的流程；这些经验之后也能迁移到模组服或 VPS。

## Java：按服务端和游戏版本选，不要只记一个数字

Java 要求取决于你下载的服务端和 Minecraft 版本。以 Paper 当前官方对照表为例：1.17–1.19 使用 Java 17，1.20–1.21.11 使用 Java 21，26.1 及以后使用 Java 25；老版本可能要求 Java 8、11 或 16。[Paper 官方入门文档](https://docs.papermc.io/paper/getting-started/)会随版本更新，因此下载 jar 后应再核对一次发行页说明。

安装完成后，在启动脚本所在的终端执行：

```text
java -version
```

看到 `UnsupportedClassVersionError` 时，优先检查这条输出和脚本实际调用的 Java 路径。电脑上同时装了多个 Java 时，`java -version` 显示的版本不一定就是你以为的那个版本。

## 内存：留余量比把数值拉满更重要

服务端需要的内存没有一个对所有服务器都成立的固定答案。人数、视距、区块生成、实体数量、插件和模组都会改变实际需求。请先从能稳定启动的保守值开始，再根据 `spark` 报告、日志和实际 TPS 调整。

- 小型原版或少量插件服务器通常可以从 `-Xms2G -Xmx4G` 开始观察。
- 大型模组包、较多玩家或高视距会需要更多内存，但 `-Xmx` 不应等于机器总内存。
- 如果同一台电脑还要运行客户端、浏览器或录屏软件，应额外留出系统余量。

你可以用[服务器内存规划工具](/tools/memory-plan)先生成一组保守参数。高内存占用本身不等于内存泄漏；更重要的是有没有 OOM、长时间 GC 停顿或容器内存限制过低。[Paper 的排错文档](https://docs.papermc.io/paper/basic-troubleshooting/)对此有更详细的说明。

## 在哪里运行服务器

| 环境 | 适合什么情况 | 需要注意什么 |
| --- | --- | --- |
| 自己的电脑 | 练习、临时和小规模好友服 | 断电、休眠、网络变化都会让玩家掉线。 |
| VPS / 云服务器 | 想长期在线且能使用 Linux 命令 | 需要自己处理系统更新、防火墙、备份和账单。 |
| 托管面板服 | 希望少管操作系统 | 仍要看资源上限、备份策略、出口网络和售后支持。 |

先在自己的电脑上跑通流程，再迁移到其他环境，通常比直接在生产服务器上边学边改更安全。

## 让朋友连接前，先理解网络边界

家用宽带常见三种路径：有公网 IP 时使用端口转发；没有公网 IP 时使用可信的隧道或中转；直接把服务端部署到具有公网地址的主机。Minecraft Java 默认监听 TCP 25565，但如果你改了 `server-port`，客户端地址、防火墙和转发规则也要一起改。

`server.properties` 中的 `server-ip` 通常应保持为空，它会让服务端监听所有可用网络接口；把公网 IP 填进去反而可能导致绑定失败。[Paper 的配置参考](https://docs.papermc.io/paper/reference/server-properties/)明确说明了这一点。

## 下一步

准备好 Java 和一个空文件夹后，继续阅读[首次开服完整流程](/docs/java/intro/setup)。先在 `localhost` 上验证服务端，再开放给局域网或公网玩家。
