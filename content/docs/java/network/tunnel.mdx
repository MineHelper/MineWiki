---
title: 内网穿透
description: 没有可用公网地址时，如何选择、配置并安全使用游戏端口中转
---

当家用网络没有可直接入站的公网地址，或者你无法控制上级路由器时，可以借助中转节点把玩家的连接转到本地服务端。这类方案常被称为“内网穿透”或“隧道”。它解决的是可达性，不会自动解决性能、账号安全或服务器配置问题。

## 它在做什么

```text
玩家 → 公网中转节点 → 加密/长连接隧道 → 你的服务端
```

本地客户端主动连接中转节点，因此即使家里路由器不接受新的入站连接，节点也能沿着已有隧道把游戏流量送回本机。玩家看到的是节点提供的地址和端口，而不是你的内网地址。

## 选择方案时看什么

| 方案 | 适合情况 | 你需要负责什么 |
| --- | --- | --- |
| 自建 frp / 类似中转 | 有一台 VPS，且愿意维护 Linux 与防火墙 | 节点安全、更新、监控、带宽和故障恢复。 |
| 托管隧道服务 | 小规模好友服，想少配一台服务器 | 服务条款、节点质量、流量限制、账号和访问令牌。 |
| 直接部署到 VPS / 面板服 | 希望长期在线或玩家较多 | 服务端本身、备份和服务器安全。 |

不要根据“免费”“延迟低”的宣传就交出访问令牌。先看服务商是否清楚说明流量限制、节点位置、数据处理方式和账户恢复政策；也不要把控制台、RCON、面板端口一起映射出去。

## 通用配置步骤

不同产品的界面和字段名称会变，但核心信息相同：

1. 在服务端电脑上确认 Minecraft 已能通过 `localhost:端口` 正常进入。
2. 在隧道客户端中填写本地目标，通常是 `127.0.0.1` 与实际 `server-port`，例如 `25565`。
3. 只创建 Minecraft 游戏端口的 TCP 映射，不要顺手暴露 RCON、Web 面板、远程桌面或 SSH。
4. 保存后启动客户端，记录它返回的公网地址和端口。
5. 用手机流量或局域网外的朋友测试；本机或同一 Wi‑Fi 的结果不能代表外网一定可用。

如果你的服务端监听在其他地址，请先检查 `server.properties` 的 `server-ip`。大多数单服场景应留空；把它固定为错误地址会导致隧道本地连接失败。

## 凭据和日志

访问令牌、配置文件和客户端日志都可能包含账号、节点或本地路径信息。不要把它们完整截图发到公开群聊；向他人求助时，应先遮掉令牌、密码、公网地址之外的敏感字段。

当玩家连不上时，按顺序看：服务端 `logs/latest.log` 是否有连接记录、隧道客户端是否显示已连接、节点是否分配了正确的外部端口、玩家是否使用了完整的 `地址:端口`。这样能判断问题是在服务端、本地隧道还是中转节点。

## 延迟与稳定性

中转会增加一段网络路径，延迟、抖动和丢包取决于你的家庭网络、节点位置和玩家网络。选择离你和主要玩家都相对近的节点通常更合理，但只有实际测试才能确定效果。

如果高峰期频繁掉线、免费额度不足，或你需要长期稳定在线，不必执着于继续换节点。迁移到具备公网网络的 VPS 或托管环境，往往更容易管理和排错。
