title: 用 Velocity 连接多个子服
description: 只有在确实需要大厅、多玩法或多后端时再引入代理，并先把后端隔离与身份转发做对

Velocity 是一个 Minecraft Java 代理：玩家连接代理，代理再把玩家转送到大厅、生存、小游戏等后端服务器。它适合多子服网络，不是单个小型服务器必须安装的“加速器”。如果你只有一台 Paper 生存服，先把备份、权限和网络做好，通常更简单可靠。

## 什么时候值得使用

| 场景 | 是否值得考虑 | 原因 |
| --- | --- | --- |
| 单一生存服 | 通常不需要 | 代理增加了 Java、配置、安全和故障排查复杂度。 |
| 大厅 + 生存 + 资源世界 | 值得评估 | 玩家可通过一个地址进入，再由代理分流。 |
| 多台机器承载不同玩法 | 值得评估 | 代理提供统一入口和后端列表。 |
| 需要隐藏后端真实地址 | 值得评估 | 但必须同时配置后端访问限制与身份转发。 |

## 最小部署思路

1. 给代理创建独立目录，按官方当前要求安装 Java 并下载稳定版本。Velocity 的 Java 要求会随版本变化，安装前请以官方入门页为准。[1]
2. 首次启动生成 `velocity.toml`，再配置 `[servers]` 中的后端名称与地址。
3. 将玩家公开入口指向代理，而不是直接指向每个后端。
4. 根据官方文档配置后端服务器、玩家信息转发和安全限制；这一步不能省略。
5. 先用测试账号验证大厅、后端转送、断线回退和权限显示，再邀请玩家。

## 后端不能直接暴露

代理网络最常见的安全错误是：玩家既能连接代理，也能直接连接 Paper 后端。如果后端对公网开放，玩家可能绕开代理、身份转发和入口限制。正确做法是让后端只接受代理所在网络或可信 IP 的连接，并按 Velocity 的安全与 player information forwarding 文档完成配置。[1]

Velocity 官方的最小配置示例会要求后端为代理连接做相应调整；不要只改 `online-mode` 后就上线。身份转发、转发密钥和后端绑定范围必须一起配置，否则可能出现玩家 UUID、皮肤、权限或安全问题。

## 维护要点

代理与每个后端都有独立日志和版本。出现玩家无法转服时，要分别查看代理日志、目标后端日志和网络连通性。更新时，先在测试网络验证代理与后端的兼容组合；不要把代理、Paper、权限插件和多个后端同时升级。
