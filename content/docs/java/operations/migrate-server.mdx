---
title: 迁移到新电脑或新主机
description: 通过整服副本、测试启动和分阶段切换迁移服务器，而不是直接移动世界文件碰运气
---

换电脑、换云主机或从家用网络迁移到托管环境时，最稳妥的目标不是“尽快把文件传过去”，而是让新环境先跑通，再让玩家切换。原服务器在确认新服可用前应保留原状，避免一次误操作同时失去可运行版本和备份。

## 先区分两种迁移

| 场景 | 风险重点 | 推荐策略 |
| --- | --- | --- |
| 同一服务端类型换机器 | Java、文件权限、端口、防火墙与完整数据复制 | 复制整服目录，在新机器隔离启动验证。 |
| Vanilla、Paper、Spigot、模组加载器之间切换 | 世界目录结构、插件/模组 API、数据格式 | 按官方迁移指南逐项处理，不把“换 jar”当成迁移完成。 |

Paper 官方说明：从 Vanilla 迁移到 Paper 前需完整备份；从 Fabric/Forge 切到 Paper 时，Paper 无法加载那些新增方块、物品或数据的模组内容，也不能加载 Fabric/Forge 模组。[1]

## 同类型迁移的推荐流程

1. 提前记录旧服务器的完整版本：服务端 jar、Java、插件/模组、启动参数、端口和域名记录。
2. 正常停服，做一份整服备份，并将归档复制到新机器以外的位置。
3. 在新机器安装与旧服兼容的 Java，解压整服副本，保留原目录结构。
4. 先只在本机或私有网络启动，查看日志，确认世界、插件和模组能加载。
5. 用测试账号检查核心玩法；此时不要让新旧服务器同时使用同一公网端口。
6. 配置新机器的防火墙、端口转发或安全组；用外网测试连接。
7. 公告切换时间，将域名或端口指向新服；保留旧服离线备份直到稳定观察期结束。

## 迁移时最常漏掉的内容

世界目录只是其中一部分。以下内容也应被纳入清单：`server.properties`、白名单、OP/封禁数据、插件与模组 jar、各自的配置目录、资源包地址、启动脚本、计划任务、面板设置以及域名 DNS 记录。是否需要迁移日志取决于排错和合规需求，但最近的 `latest.log` 往往能帮助新环境定位问题。

## 从 Paper 切回 Vanilla 要特别谨慎

Paper 与 Vanilla 的世界目录组织在不同版本中可能不完全相同。官方迁移指南按目标 Vanilla 版本给出了需要移动的维度与数据文件；如果没有按指南操作，下界或末地可能看起来像被重置。遇到这种情况不要立即删除目录，先停服、保留现场并按版本对应的官方流程检查。[1]

## 迁移完成后的验证

| 验证项 | 要确认的结果 |
| --- | --- |
| 日志 | 没有缺失 jar、Java 或权限相关的启动失败。 |
| 世界 | 主世界、其他维度、玩家位置和关键建筑均正常。 |
| 扩展 | 关键插件/模组、配置和数据文件被实际加载。 |
| 网络 | 外部玩家可以通过最终域名或地址连接。 |
| 回滚 | 原机器或完整归档仍可恢复，不依赖新环境中的唯一副本。 |
