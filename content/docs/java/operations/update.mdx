---
title: 服务端与插件更新
description: 用备份、兼容性检查和测试副本完成可回滚的更新，而不是赌一次替换能成功
---

更新并不天然危险，危险的是在没有备份、没有版本记录和没有回滚计划的情况下更新。无论是 Minecraft 大版本、Paper 构建、插件、模组还是 Java，先确认兼容关系，再决定是否上线。

## 什么时候该更新

- 官方发布安全修复、严重 bug 修复或你正在遇到的问题已有明确修复时，应安排测试。
- Minecraft 大版本更新时，不要用“等待固定几天”作为标准；先确认玩家客户端、服务端、核心插件/模组、依赖库和备份恢复流程都已准备好。
- 小版本也可能改变数据格式或 API。更新前仍要看服务端和插件的发行说明。

世界降级通常不受支持。Paper 的官方排错文档明确提醒：世界被较新版本加载后会升级，之后再用旧版本打开可能出现“chunk saved with newer version”错误。[Paper：Basic troubleshooting](https://docs.papermc.io/paper/basic-troubleshooting/)

## 更新前的检查表

1. 创建可恢复的整服备份，并确认归档能打开。
2. 记录当前服务端、Java、关键插件或模组的完整版本。
3. 列出核心功能：登录、传送、权限、经济、领地、模组世界生成等。
4. 阅读服务端和关键扩展的发布说明，特别关注破坏性变更和迁移步骤。
5. 若服务器对外长期运行，尽量先在测试目录或测试主机演练一次。

## 推荐流程

1. 宣布维护窗口并正常停服。
2. 将当前目录完整备份；保留可启动的旧 jar、旧脚本和版本记录。
3. 只替换本次计划更新的文件，不要顺便大改配置。
4. 先在测试目录启动，查看 `logs/latest.log`，确认没有加载失败、缺失依赖或数据迁移错误。
5. 进入游戏逐项测试核心功能，再让少量管理员或玩家验证。
6. 一段观察期后再清理旧版本；在此之前保留回滚所需文件和备份。

## 出现问题如何回滚

先停服并保存当前日志。若问题确认由本次更新引起，恢复到**匹配的整套版本组合**：服务端、插件/模组、配置和世界数据不能随意交叉拼接。恢复后重新启动并验证世界和核心功能。

不要因为世界“看起来消失”就立即新建世界。先检查 `level-name`、工作目录、备份日期和服务端日志；很多情况是加载了错误目录或启动参数，而不是真正丢失数据。

## 插件和模组更新的额外注意

插件更新前要确认 API、前置库和 Java 版本；模组更新还要确认客户端和服务端包是否同时更新。NeoForge 官方要求在更新 NeoForge 或模组前备份世界。[NeoForge：Installing a Server](https://docs.neoforged.net/user/docs/server/)

自动更新不是不能用，但它应该建立在你理解来源、校验、备份和回滚行为的前提上。对新手服务器而言，记录每次变更并手动验证，通常更可控。
