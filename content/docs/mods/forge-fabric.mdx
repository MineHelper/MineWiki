# Forge 还是 Fabric

选加载器之前先记住这句话：**你想要的模组决定了加载器，而不是反过来**。先把你想玩的模组/整合包确定下来，再看它是基于哪个加载器。

## 对比

| 维度 | Forge / NeoForge | Fabric |
| --- | --- | --- |
| 模组数量 | 最多，老模组基本都是 Forge | 少于 Forge，但日常够用 |
| 更新速度 | 新版本适配慢，经常要等 | 适配快，新版本发布后很快跟进 |
| 性能 | 中等，加载更重 | 更轻快，启动和运行都更省 |
| 兼容性 | 老模组多，但新老混装易冲突 | 模组间冲突相对少 |
| 新手友好度 | 生态大，教程多 | 概念更清晰，文档规范 |

## 怎么选

- **你想玩的整合包 / 核心模组是 Forge 的**：没得选，直接 Forge。
- **想要最流畅、模组不在多而在于精**：Fabric。
- **拿不定主意**：查你想要的模组在哪个加载器上，`modrinth.com` 每个模组页面都会标注支持的加载器。
- **明确想玩光影、科技、魔法大整合**：大概率是 Forge 生态，走 Forge。

## 记住这个坑

同一个模组，Forge 版和 Fabric 版是**两个不同的文件**，不能混用。下载时看清"平台/loader"标签。装错加载器，启动器会直接报错或者干脆不识别这个模组。

## NeoForge 是什么

Forge 团队把项目交接给了 NeoForge 社区，新一代 Forge 就叫 NeoForge。如果你从没接触过 Forge，直接上 NeoForge 就行；如果整合包明确要求旧版 Forge，就按整合包要求来。**跟着整合包走，别自己开脑洞。**

## 一句话

确定模组 → 查加载器 → 下载对应版本。加载器本身不用纠结太久，模组生态替你做了决定。
