## 模组服入门

插件和模组的运行方式不同。多数 Bukkit/Paper 插件只在服务端运行；模组则可能是客户端专用、服务端专用或两端都需要。是否需要玩家安装，必须以模组作者或整合包的说明为准。

## 模组和插件到底有什么区别

- **插件（Plugin）**：通常由支持 Bukkit/Paper API 的服务端加载。客户端一般不需要额外安装文件，但仍可能需要资源包或特定玩法规则。
- **模组（Mod）**：由 Forge、NeoForge 或 Fabric 等加载器加载。它可能只在客户端、只在服务端，或两端都需要安装。
- **数据包（Datapack）**：原版支持的世界数据与函数机制；它不等于模组，也不需要加载器。

新手最容易踩的坑就是**把模组服当成插件服来理解**。模组服的客户端安装、版本对齐、启动方式都比插件服麻烦一截，做好心理准备再入坑。

## 两种主流加载器

- **Forge**：许多既有整合包和模组明确要求的加载器。
- **NeoForge**：独立的现代加载器项目，部分新项目会明确发布 NeoForge 构建。
- **Fabric**：另一套独立生态，许多 Fabric 模组会依赖 Fabric API。

选哪个？先看整合包或核心模组明确写的加载器与版本。Forge、NeoForge 和 Fabric 的模组文件不能互换。

## 开模组服前先想清楚

1. **整合包还是自己组模组**：整合包能减少初始的兼容性工作，但仍要按作者说明部署 server pack。自己组包时，应记录每个模组、依赖和配置版本。
2. **负载来源**：大型内容模组、世界生成、实体和自动化都可能提高服务端负载；光影通常是客户端负载，不能用它判断服务端内存需求。
3. **兼容关系**：Minecraft 版本、加载器和需要两端安装的模组必须匹配。出现“版本不兼容”时，先读报错中点名的模组与依赖。

## 常见的心态误区

- **"模组装得越多越好"**：错。每个模组都可能拖慢加载、产生冲突，整合包删模组要谨慎。
- **“原版客户端一定不能进入模组服”**：这取决于服务端安装的模组与加载器网络要求。不要猜；以整合包或模组的客户端需求说明为准。
- **“Fabric API 是插件生态”**：Fabric API 是许多 Fabric 模组依赖的 API，并不是 Bukkit/Paper 意义上的插件系统。服务端模组同样需要处理版本、冲突和更新。
