## 模组服入门

插件服和模组服是两条完全不同的路。插件在服务端运行，客户端什么都不用装；模组则讲究**客户端和服务端两边一致**。这篇把模组服最基础的概念讲清楚。

## 模组和插件到底有什么区别

- **插件（Plugin）**：跑在服务端上，玩家客户端无感。之前《插件》章节讲的都是这个。
- **模组（Mod）**：改的是游戏本身。客户端装了才有效果，服务端要装对应的模组才能联动。
- **数据包（Datapack）**：原版就支持的轻量"官方机制"，不用装模组也能做很多事情，可以看作介于两者之间。

新手最容易踩的坑就是**把模组服当成插件服来理解**。模组服的客户端安装、版本对齐、启动方式都比插件服麻烦一截，做好心理准备再入坑。

## 两种主流加载器

- **Forge**：老牌，模组数量最多，生态最成熟。
- **Fabric**：轻量、启动快、更新及时，现代模组玩家偏爱。
- （NeoForge 是 Forge 的分支，新一代 Forge，也值得关注）

选哪个？先看**你想玩的整合包里是哪个加载器**——整合包决定了加载器，反过来选加载器再找模组，你会很痛苦。

## 开模组服前先想清楚

1. **整合包还是自己组模组**：新手强烈建议直接跑整合包（CurseForge 上有现成的），自己组模组要处理版本匹配，很容易崩到怀疑人生。
2. **服务器配置要求比插件服高**：很多大型模组（尤其是光影、科技类）本身就吃配置，服务端要更大内存。
3. **客户端版本和服务端必须一致**：玩家连进来说"版本不兼容"，多半是客户端和服务端版本对不上，或者是两边模组列表不一致。

## 常见的心态误区

- **"模组装得越多越好"**：错。每个模组都可能拖慢加载、产生冲突，整合包删模组要谨慎。
- **"原版玩家也能进模组服"**：原版客户端进模组服会直接失败，别指望"兼容"。
- **"模组服没插件"**：Fabric 有 Fabric API 生态，很多"插件"其实是服务端模组，同样有安装、冲突、更新问题。
