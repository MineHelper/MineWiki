# 端口转发

端口转发（Port Forwarding）的作用一句话讲清楚：让你家路由器把外面进来的、指向某个端口的流量，转交给局域网里运行服务端的那台电脑。

## 前提：你必须有公网 IP

先确认你家宽带有公网 IP。怎么看：

- 打开 https://www.ip.cn 这类查 IP 的网站，记下显示的 IP。
- 再打开路由器后台看"WAN 口 IP"。
- 两个 IP 一致，说明你有公网 IP；对不上，基本就是运营商给你 NAT 了一层，端口转发做了也白做。

国内运营商这种情况很常见，没有公网 IP 就直接看《内网穿透》那篇，别在这死磕。

## 找到你的内网 IP

服务端所在电脑，在命令行（Win+R 输入 `cmd`）里运行：

```
ipconfig
```

找到"IPv4 地址"，一般是 `192.168.x.x`，记下来。

## 进路由器后台

浏览器打开 `192.168.1.1` 或 `192.168.0.1`（不确定就看你路由器背面标签），用管理员账号登录。没改过的话账号密码通常是 `admin/admin`。

不同品牌的路由器后台长得完全不一样，但功能名都差不多，找这几个关键词：**端口转发 / 虚拟服务器 / 转发规则 / Port Forwarding / Virtual Server**。

## 填规则

以常见的 TP-Link 界面为例，要填的大概是这些：

| 项目 | 填写 |
| --- | --- |
| 服务端口 / 外部端口 | 25565 |
| 内网端口 | 25565 |
| IP 地址 | 你查到的 `192.168.x.x` |
| 协议 | TCP |

这里有个最常见的坑：内网 IP 是动态的，重启电脑或路由器后可能变。建议把服务端那台电脑的 IP 在路由器里设置成**静态 / 保留地址（DHCP 保留）**，否则哪天 IP 变了，转发规则全废。

## 验证

规则填完先别急着发地址，自己验证一遍：

1. 确认服务端正在运行。
2. 用另一台设备（比如手机用流量）连接 `你的公网IP:25565`。
3. 能连上，说明转发成功；连不上，从下面几项排查。

## 排查清单

- 服务端真的在跑吗？`server.properties` 里的 `server-port` 是 25565 吗？
- 电脑防火墙放行 Java 了吗？Windows 防火墙第一次启动服务端时弹出的"允许"对话框，很多人随手点了取消。
- 协议选对了吗？MC 的联机流量是 TCP，有的路由器默认 TCP/UDP，一般没影响，但别只选 UDP。
- 本地电脑和手机连的是同一个 Wi-Fi 吗？本地设备测试要避开同一个局域网，否则绕过了公网路径，测不出来。

## 常见误区

- **本地测试连不上就断言转发失败**：同一个 Wi-Fi 下测试会走局域网，可能测不出来，用手机流量测最靠谱。
- **把内网 IP 发给别人**：前面说过，内网地址对外无效。
- **改 `server.properties` 里端口还连不上**：改了端口，转发规则和连接地址要一起改，三处必须一致。
