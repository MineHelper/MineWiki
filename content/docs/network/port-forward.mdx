---
title: 端口转发
description: 将公网游戏流量转到局域网中的服务端，并用外网测试验证整条链路
---

端口转发让路由器把到达公网端口的流量交给局域网中的一台电脑。对于 Minecraft Java 服务端，通常转发的是 TCP `25565`；如果你在 `server.properties` 中改过 `server-port`，则应使用新端口。

## 先确认端口转发是否有机会成功

端口转发需要你能够控制一台拥有可入站公网地址的路由器。打开“查 IP”网站记录外部地址，再进入路由器后台查看 WAN/Internet 地址：

- 如果 WAN 地址是 `10.x.x.x`、`172.16.x.x–172.31.x.x`、`192.168.x.x` 或 `100.64.x.x–100.127.x.x`，它不是可直接入站的公网 IPv4 地址。
- 如果外部地址和 WAN 地址不同，通常存在上级路由、光猫路由模式或运营商 NAT；此时需要先理清网络拓扑。
- 即使两者相同，也不代表运营商或防火墙一定允许入站连接，仍必须进行外网测试。

没有可用公网入口时，不必反复改路由器规则；改用[内网穿透](/docs/network/tunnel)或把服务端部署到有公网网络的主机更合适。

## 找到服务端电脑的局域网地址

在 Windows 命令提示符中运行：

```text
ipconfig
```

记录当前网卡的 IPv4 地址和默认网关。局域网地址不一定都以 `192.168` 开头，也可能是 `10.x` 或 `172.16–31.x`。建议在路由器中为这台电脑设置 DHCP 地址保留，避免重启后地址变化导致规则指向错误设备。

## 登录路由器并创建规则

使用 `ipconfig` 显示的**默认网关**进入路由器管理页，或查看路由器标签/官方说明书。不要猜测管理员账号和密码，更不要长期保留厂商默认密码；登录后如仍使用默认凭据，应立即按路由器说明修改。

不同厂商的菜单名称不同，常见关键词包括“端口转发”“虚拟服务器”“NAT”“转发规则”。建立一条规则时，填写内容通常如下：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 外部端口 | `25565` | 玩家从公网访问的端口。 |
| 内部地址 | 服务端电脑的局域网 IPv4 | 应与 DHCP 保留地址一致。 |
| 内部端口 | `25565` | 应与 `server-port` 一致。 |
| 协议 | TCP | Java 版游戏连接使用 TCP。 |

只转发玩家需要的游戏端口。不要顺带开放 RCON、远程桌面、SSH 或面板端口。

## 系统防火墙也要允许连接

路由器规则生效后，Windows、Linux 或主机安全组仍可能阻止入站连接。确认防火墙只允许对应 TCP 端口或 Java 服务端进程，不要为了测试而暂时关闭整个防火墙。

同时检查 `server.properties`：`server-port` 是否与规则一致，`server-ip` 通常是否留空。Paper 文档说明，空的 `server-ip` 会绑定所有可用网络接口。[Paper：server.properties](https://docs.papermc.io/paper/reference/server-properties/)

## 用真正的外网路径测试

1. 确认服务端正在运行，并先在本机用 `localhost` 连通。
2. 使用手机流量、外地朋友或其他确实不在同一局域网的网络，连接 `公网地址:端口`。
3. 测试成功后才把地址发给其他玩家。

有些路由器支持 NAT 回环，有些不支持。因此在同一 Wi‑Fi 下用公网地址测试失败，不能单独证明端口转发错误；用手机流量通常更有参考价值。

## 仍然连不上时

按这个顺序排查：服务端是否运行、脚本是否监听正确端口、系统防火墙是否允许、路由器规则的内部地址是否仍正确、WAN 是否存在上级 NAT、外部测试是否确实离开了本地网络。把这几项的结果和 `logs/latest.log` 的相关时间段一起整理，再向运营商或社区求助。
