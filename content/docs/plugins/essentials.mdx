## 常用插件清单

先说规矩：**插件不是越多越好**。每多一个插件就多一分冲突和卡顿的可能。下面这份清单是"够用"的标准，按需取用，别照单全收。

## 按需求选择的常见基础组件

| 插件 | 作用 | 说明 |
| --- | --- | --- |
| EssentialsX | 常见的基础命令集合（如 `/home`、`/tpa`） | 适合需要这些命令的生存服；先查看模块与权限说明。 |
| Vault | 经济、聊天或权限插件常用的桥接 API | 只有目标插件声明依赖它时才安装。 |
| LuckPerms | 细粒度权限管理 | 可替代“给很多人 OP”的粗放做法。 |
| WorldEdit / WorldGuard | 区域编辑与保护 | 常被一起使用；具体依赖与安装顺序以发布页说明为准。 |

这些不是每个服务器都必须安装的“四件套”。先写下你要解决的功能，再选择最少且互相兼容的插件。

## 推荐考虑

- **EssentialsX 附属模块**：家、邮箱、聊天前缀等，按需启用。
- **CoreProtect**：方块操作日志，防熊、回滚的利器，出了事能查"谁动了我的房子"。
- **Slimefun / 类插件**：想搞点玩法深度再上，别新开服就装，机制太重。
- **DiscordSRV**：服务器和 Discord 互通，国内用得少，按需。

## 别急着装的

- 没有性能报告支撑的“优化”插件：先用 spark 找到热点，再评估具体插件是否能解决该问题。
- 还没有测试兼容性的功能插件：先在测试副本中试运行，避免一次叠加多项玩法后难以回滚。
- 来源不清、被二次打包或要求运行额外安装器的文件：插件会在服务端进程中执行，应只从作者声明的渠道获取。

## 装完顺序建议

1. 先决定成员管理方式：白名单、OP 数量和是否需要权限插件。
2. 每次只安装一个功能组件，启动后检查日志并在游戏内测试。
3. 只有目标插件声明需要时，再安装 Vault、WorldEdit 或其他前置。
4. 为每次成功配置创建备份或版本记录，再继续增加功能。

这个顺序的核心思路：**基础命令和权限先通，再谈别的**。权限没配好就装一堆功能插件，你连谁有权用什么命令都理不清。

## 插件自带配置别急着改

大部分插件默认配置对新手够用，别一上来就把 `config.yml` 从头改到尾。先用默认跑着，遇到具体需求再去文档里找对应配置项——插件文档（一般是插件下载页或 GitHub README）比任何教程都准确，别人转载的教程很可能过期。
